# Tests

`capability-health.test.mjs` verifies explicit flags/states, bounded shared refresh, ignored abort/disposal, stale observations, service identity/readiness, additive contract/schema linkage and static dashboard labels. Actual isolated servers prove host-only refresh, player projection and Party zero-probe behavior. AI probe transport is covered in `remote-ai.test.mjs`. See [readiness meanings and limits](../docs/capability-health.md).

`remote-ai.test.mjs` checks explicit off-host consent, loopback/LAN/remote classification, provider aliases and Party override, then starts source/emitted adapters in nine allowlisted environments with fake fetch. Blocked cases make no request; allowed cases refuse redirects and use only the selected provider; local failure cannot trigger cloud fallback. See [configuration policy](../docs/runtime-configuration.md#remote-ai-consent).

`narration.test.mjs` checks prepared fallback, bounded completion (including ignored abort), scope changes, replacement/caller/shutdown cancellation, and actual delayed draft/roll replies across advancement/reset. Current results work; exact roll receipt replay submits no extra narration. All provider replies are synthetic, with the bounded test-only delay isolated in the fixture helper. See [narration boundaries](../docs/narration.md).

`ttrpg-action-routes.test.mjs` verifies atomic group-action completion through actual source/emitted handlers: an injected final-roll receipt failure restores rolls, history, action, narration and revision; retry/replay/restart preserve one outcome. Original synthetic characters and blocked optional services keep this independent of real campaigns or providers. See [action route boundaries](../docs/server-refactor.md#action-controls-and-rolls).

See the [verification matrix](../docs/verification-matrix.md) for requirement coverage, exact limits and outstanding rendered/physical release gates.

`character-routes.test.mjs` checks actual source/emitted character/claim handlers with original synthetic sheets. It verifies creation defaults/validation, denied access, atomic failure and exact restart replay; claim identity normalization, note privacy, conflicts and display denial; switch/release rollback; competing stale-revision commands; and replay of an old claim after release/another player's claim without changing current ownership. Existing command/session middleware remains responsible for authority and durable commit. See [character extraction](../docs/server-refactor.md#character-creation-claims-and-release); rendered claim/creation interactions remain unverified.

`state-events.test.mjs` selects source/emitted state owners and actual isolated approval routes. Four cases cover all five kinds, clamps, condition no-ops, fresh lookup after rollback replacement and invalid queued values. Real API checks preserve player ownership/submitter identity, deny player approval/direct/queue access, and verify receipt-failure rollback including deferred memory files, exact retry/restart replay and rejection. A synthetic persisted malformed initiative proposal returns 400 while preserving initiative/queue/revision. This application guard does not complete validation of all loaded records or scene packets; see [state/approval extraction](../docs/server-refactor.md#state-event-application-and-approval-routes).

`table-read-routes.test.mjs` checks source/emitted summary formatters and actual extracted read routes. It verifies unauthenticated denial, compact roll compatibility across host/player/display, party field allowlists, projected snapshots, no non-host summary disk writes, private host export headers/content and a generic host error with an owned obstructed export path while player summaries keep working. Pure populated/empty cases cover deterministic formatting, filename sanitization and input preservation. The unreachable duplicate GET roll handler is removed; current POST and snapshot/frame consumers retain their contracts. See [server extraction](../docs/server-refactor.md); further ENGINE-01 work and rendered TTRPG acceptance remain open.

`command-history.test.mjs` selects source/emitted store and Party service modules, checks global metadata bounds across rooms/modes, backward clock movement, explicit truncation/empty windows, exact preserved receipt conflicts/checkpoints, invalid policies and transactional retention failure. Seven synthetic players resolve/recover a round without reroll or republish on replay after eviction. An actual isolated process restarts after more than 5,000 owned fixture envelopes and replays an evicted roll's exact receipt. Only redundant metadata expires; user/domain records, receipts and checkpoints remain. See [policy and limits](../docs/command-history.md); this does not bound total database size or establish a full audit archive.

`schema-migrations.test.mjs` selects source/emitted modules with `BDE_TEST_BUILT`. Six synthetic cases verify ordered additive versions, atomic failure rollback, exact legacy JSON/authority/receipt preservation, incompatible/foreign/history/future-version refusal, and SQLite online backup of WAL writes followed by independent disposable restore/adoption. Connections and ignored `tmp/migrations-*` fixtures are owned and cleaned up. No real data is migrated. See [schema and backup compatibility](../docs/schema-migrations.md); runtime main-file-copy backups and the full product restore workflow remain unverified; bounded metadata retention has its own fixture.

`host-client.test.mjs` checks malformed live host envelopes, bounded saved-roll presentation dedup, authenticated real-server reconnect and roll/snapshot delivery, and static output from seven extracted host panels. It does not provide browser layout or React-effect mounting evidence; shared transport lifecycle tests remain in `party-connection.test.mjs`.

It also applies an HP command through the extracted table interface and renders the interactive table/approval/character and scene/AI panels with synthetic data. `host-table-actions.test.mjs` checks uncertain-reply request-ID/draft retention, confirmed clear, fresh intentional commands, approval routing, rejected responses and storage failure before submission. This is not yet a full room-scoped host queue or browser interaction proof.

Run `npm test` using the installed Node test runner and `tsx` loader, after `npm run build` for emitted-service tests. Synthetic TTS checks also require an existing `python` 3.10+ interpreter on PATH (standard library only). No downloads or external services are required. Integration tests start owned loopback servers; the execution sandbox must permit local connections.

`session-launch.test.mjs` verifies full startup outside cwd with selected audio/router children, occupied-port refusal before database creation and cleanup of owned listeners/processes. `tts-config.test.mjs` invokes isolated Python checks with backend imports rejected, synthetic model-file placeholders, port-conflict-before-model-load checks and injected speech/WAV responses. Live speech/model quality and inference cancellation are not tested.

Root pretest/prelint build `packages/contracts` and `packages/runtime-config` first. Development prerequisites build the packages their consumers require. Root build participates in eight workspaces, with both shared packages before their consumers. `contracts.test.mjs` verifies producer/view shape compatibility, malformed nested state, persisted-corruption refusal and strict metadata/request IDs. JSON Schema checks are targeted enum/identifier parity, not complete schema validation or generation. No workspace-link installation is required for current relative entrypoint imports.

`legacy-persistence.test.mjs` explicitly opens owned ignored `tmp/persistence-*` stores or injects independent memory connections. It verifies import safety with invalid configuration canaries, rollback across nested/outer transactions, all legacy table round trips/order, WAL/FULL, close/reopen and asset status persistence. The database module does not open a store on import; the server entrypoint still explicitly opens its configured database on execution. Source and emitted modes select the corresponding persistence module. Fixtures close owned handles and remove only their own directories. See [ownership and compatibility](../docs/game-store.md). No server, `.env`, `_data`, model or optional service is accessed by these persistence unit checks.

`legacy-api.test.mjs` verifies authenticated TTRPG join/claim/roll/approval/export, server-side projections, actual socket frames, forged-role and ownership denial, revoked sockets and membership resume after a real child-process restart. It injects a SQLite receipt-write failure, verifies rollback and successful retry, then crashes without save-now and checks exact recorded-roll replay, revision and HP recovery. Set `BDE_TEST_BUILT=1` after building to exercise emitted JavaScript without a TypeScript loader in the server child.

Authority tests cover expiry with injected time, recovery, hashed credential persistence, new-room invalidation and header parsing. Projection tests use synthetic private canaries and unknown fields. Command-store tests cover canonical payloads, scope, stale revisions and rollback across legacy writes, state, receipt and event. Runtime command tests reject malformed envelopes and unsafe values.

`party-game.test.mjs` verifies five complete rounds, prepared thresholds, score/danger/ties, fixed-seat resolution, private replacements, late arrivals, deadlines/pass/skip, pause/extend/resume and atomic persistence failure. `party-api.test.mjs` uses seven independent phone WebSockets plus host/display, concurrent choices, actual payload privacy checks, a complete ending and process restart during choosing, locked, reveal and resolution. It replays exact prior outcomes and verifies new-room isolation with outgoing fetch blocked. These are synthetic clients; rendered UI, physical phones/Wi-Fi and 20–30-minute pacing remain open.

`party-client.test.mjs` checks pending request restoration, exact retries/single-flight behavior, definitive versus ambiguous errors, malformed replies/storage failure, and static React markup separating TV/host/phone surfaces. `party-connection.test.mjs` checks socket/timer ownership, reconnect/wake/sleep, stale callback suppression and revocation without a browser. The API test runs the actual client queue through a lost reply after commit and loads all three built surfaces/assets. These do not replace interactive browser, visual layout or real mobile checks.

`player-client.test.mjs` checks TTRPG nested snapshot validation, latest ownership, stale revisions, receipt/socket roll deduplication, scoped pending requests and unverified receipt retention. Static markup covers own sheet fields, explicit claim/release and disabled/action modifiers. Its isolated server flow claims, loses a roll reply after commit, restarts the server, restores/retries the exact pending body, rolls the same action with a fresh ID, then releases and verifies private notes disappear. It works against both source and emitted server execution. Shared `.mts` helpers are explicit ESM; no dependency installation is required. Rendered layout, WebGL/audio/motion/focus and real mobile sleep behavior remain unverified.

`dice-presentation.test.mjs` uses real in-memory Three.js resources with fake rendering/audio/time adapters. It proves owned geometry/material/texture/image disposal, cancellation of frames/listeners/canvas, late load/failure handling, setup failure cleanup, reentrant disposal and independent sound timer ownership/rejected-playback cleanup. It creates no browser/WebGL context. Party API tests use HEAD-only metadata checks for six dice models and the sound at both built app routes; rendered/device checks remain open.

`service-config.test.mjs` starts the three auxiliary Node services from an unrelated synthetic cwd with an invalid fixture `.env`, allowlisted environment, ephemeral loopback ports and outgoing requests blocked. It verifies startup, empty audio library and repository registry lookup without opening data/backups. Its separate adapter subprocess compares actual scene/director system prompts to maintained files using fake fetch. Both cases select source/emitted execution with `BDE_TEST_BUILT`. Pure config tests cover root-relative paths, strict ports/endpoints and Party isolation. No private `.env` or model service is loaded.

`party-launch.test.mjs` runs the built launcher from an unrelated temporary directory, checks occupied-port refusal without database creation or stopping its owner, then restarts with the same credential/seat. Its separate compiler fixture deliberately exits with an error and proves startup stops. All subprocess environments are allowlisted. `party-profile.test.mjs` checks the disabled AI adapter before any fetch. The seven-client Party integration now runs explicitly in Party profile with configured provider canaries; direct optional routes and polling reads are disabled, and outgoing fetch remains blocked. Run `npm run build:party` before tests that use built surfaces/launcher.

`node tests/helpers/demo-server.mjs` starts a disposable built server for rendered checks with the same safe environment and blocked outgoing calls. It prints only the loopback address, room code and fixture folder. Send input to its process to stop it and clean up; it also handles signals. Never substitute a live campaign database.

`npm run inventory` refreshes `docs/source-inventory.md` without importing application code. Root lint/build skip workspaces without scripts: check participation in their output and inspect emitted artifacts.

`host-gallery.test.mjs` injects requests and time to check sequential reads, abort deadlines, cleanup, late completion suppression, invalid responses and recovery; static markup covers gallery states. `host-youtube.test.mjs` checks latest-selection wins, cancellation and opt-in iframe markup using fake time. No image files, browser, media provider or audio hardware are accessed. These checks do not mount React effects or prove focus, layout or embedded volume control.

`host-media.test.mjs` injects manual media requests to verify endpoint/body compatibility, confirmed snapshot/runtime updates, pressure denials and busy-state release on unavailable services. Static markup covers failed/running jobs, separate metadata, unconfigured audio, tracks/playback and cue states. It does not exercise a media provider or mount audio polling. The stdlib TTS fixture also uploads a valid full 64 KiB body and checks invalid/oversized Content-Length rejection from headers without uploading a refused body; this avoids a Windows TCP close/upload race while preserving admission checks and confirming no synthesis on rejected headers.

`host-controls.test.mjs` verifies authenticated reports, scene success/rejection, memory creation, save, Markdown bytes/path and restart with the isolated server. Injected clients check failed/malformed confirmations, abort deadline, disposed-generation suppression and owned download URLs. Static panels distinguish save/export feedback and retained scene drafts. The scene test adapter supplies the request ID that the browser credential adapter normally adds; it does not test a mounted credential UI. `narration-playback.test.mjs` injects fake audio/context/time completion to verify rejection cleanup, natural end, late decoding and context/source/URL release. No real speech is requested. Full App imports remain Vite-owned; Node tests render extracted panels, not browser hooks or effects. All browser/device/download-dispatch gates remain open.

`host-contracts.test.mjs` checks the authenticated host producer against shared nested guards, then corrupts individual protocol, character, context, memory and queue fields. Rejected connected frames apply neither half; malformed HTTP confirmations do not return success. Pure cases cover diagnostic/audio records and live adapter variants. These checks preserve the separate player/public projections; they do not prove JSON Schema parity, all legacy persistence validation or remaining controller response adoption. No provider is contacted.

`host-responses.test.mjs` runs generated scene packets through all three queues, validates the real bare-character response and drives manual media actions through the actual producer. It detects generated memory-beat drift with targeted shared-enum/schema parity. Malformed JSON/nested response cases check the shared dashboard read boundary; table/media tests verify no prior state, retry ID or draft is discarded. `service-config.test.mjs` now also checks actual library/playback responses with one owned synthetic metadata file and play/volume/mute/pause/stop state transitions. That service records playback metadata; no device audio, decoding or audible playback is tested. No browser effect mount or full JSON Schema validation is claimed.

`ai-actions.test.mjs` checks the complete proposal schema artifact, strict JSON/fenced parser, known skills/difficulty and bounded strings. An isolated server child uses canned in-process completions at one exact synthetic adapter URL; no network/model/provider is contacted. The test proves proposals/rejections do not change the action, explicit host application sends the correct contract and survives restart, validation logs exclude a rejected-output canary, and malformed/mismatched controls fail. Static markup checks retained proposals and confirmed-setting feedback; mounted effects and rendered interactions remain unverified.

`audio-cue-playback.test.mjs` checks nested library validation, matching playback confirmations, no-match/failed responses, concurrent cue sharing, deadline/disposal and late library suppression with injected fetch/time. Its authenticated server fixture scripts exact synthetic loopback URLs in-process and verifies that malformed service replies preserve queued state until a matching confirmation. No audio device, decoded media, private library or provider is accessed. Confirmation describes service metadata, not audible sound.

`media-router.test.mjs` checks prepare/submit/status shape and matching identities, refusal of the former top-level status assumption, HTTP failure body exclusion, single-flight polling, retry after failure and suppression after manual termination/replacement/reassignment. An authenticated fixture verifies malformed preparation leaves a failed job with no accepted router/prompt ID. The auxiliary-service fixture now validates actual router prepare/status producers from unrelated cwd against shared guards in source and built modes. All calls are injected/blocked or loopback synthetic services; no workflow execution, GPU, private output or real ComfyUI is used. These tests do not establish generated-file availability, durable submission recovery or full session/revision cancellation.

The authenticated host response fixture also saves generated asset metadata and verifies its exact records after restart. This catches the formerly omitted required SQL asset status; it proves metadata persistence, not generated file availability or approved file serving.

`server-lifecycle.test.mjs` selects source/emitted lifecycle and dice modules. It injects timer/time/transport and authoritative die outcomes, checks ignored/caller abort and stopped callbacks, and closes real owned HTTP/WebSocket listeners. A stalled response proves bounded drain; failed flush still closes storage once. An isolated actual game server holds an authenticated socket and stalled synthetic audio lookup, then test-only IPC delivers SIGTERM and verifies zero exit plus persisted cues. It never force-stops the process on the successful path. No production IPC handler or shutdown endpoint is added. Real OS termination, physical devices and live providers remain outside this check. See [ownership and limits](../docs/server-lifecycle.md).

Speech and automatic scene-image owners: `speech.test.mjs` exercises scoped shared synthesis, one-active/two-waiting admission, deadline/cancellation, bounded cache and WAV envelope checks with synthetic bytes. `scene-images.test.mjs` verifies current-scope bounded attempts, submission acknowledgment validation, ignored abort/body, Party zero-call behavior, and real command rollback/replay/restart without duplicate submissions. The group-roll fixture also proves one post-commit image request across rollback/replay/restart. See [optional-work limits](../docs/optional-work.md); no real speech or GPU work runs.

It also verifies automatic process-start/graceful-end snapshots and startup failure/manual recovery. Other fixtures opt out of automatic backups explicitly. `diagnostics.test.mjs` checks bounded metadata, secret/source canaries, export-failure isolation and AI body/deadline handling. `resource-monitor.test.mjs` checks injected pressure boundaries and real host measurement/privacy. `party-load.test.mjs` measures 75 commands across five rounds with seven players plus host/display, reporting loopback p95/max and hardware/runtime conditions. Physical Wi-Fi/phone/browser acceptance remains open.
