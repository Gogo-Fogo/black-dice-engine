# Operational diagnostics and measured pressure

The game server keeps at most 24 AI metadata entries and 24 error entries. AI log exports overwrite one bounded JSONL window under the configured export root. They contain fixed operation summaries, generated IDs, a UUID correlation ID or `redacted`, allowlisted nonnegative counts/flags, and an error-present flag. Scene titles, prompts, generated prose, filesystem paths, raw errors, arbitrary detail objects and provider bodies are excluded. Error entries use fixed recovery text and GM-only visibility. Non-host runtime projections omit these logs and resource measurements. This metadata window is not an audit history.

An export failure leaves the in-memory window available and does not fail the operation that produced it. One generic console warning is emitted per uninterrupted export-failure episode. A successful export allows a later failure to produce a new warning. Persistence diagnostics also exclude native exception text. Private session snapshots and backups remain private; this policy does not make their content public-safe.

AI completion transport accepts JSON responses up to 256 KiB and textual content up to 64,000 characters. A deadline covers transport and streamed body reads, including mocks that ignore cancellation. Non-success bodies are canceled without reading; adapter errors are generic. Redirects and provider fallback remain disabled. Structured action output passes the action contract before it can be offered for explicit host approval.

`ai-context.ts` constructs all four production input paths. Public narration receives only public-demo locations/events and facts inherited from a public campaign-bible container. Player-only records are excluded because shared speech may be heard by everyone. GM guidance/action proposals may include private context with its source kind and visibility preserved. Source paths, raw payloads, character notes/inventory and NPC secrets are not part of this context. Source kinds/text are bounded, provider context is copied, and system policies treat it as data rather than executable instructions. Narration refuses wrong-audience or privately labeled context before any provider call. GM output remains a host-only proposal; it is not automatically published or applied. This limits data exposure; it cannot guarantee factual accuracy or safe generated prose. Prepared draft material remains subject to host review.

The explicitly owned resource monitor samples process RSS/heap, host free/total memory and event-loop p95 delay, caching a window for one second and stopping its histogram during shutdown. Event-loop delay remains null until sampled. No GPU, VRAM or inference performance is inferred. Runtime status marks GPU capacity `unmeasured`; invented 1/2/5 ms core-service latencies were removed. Read-only capability probes retain their measured request latency.

Queue pressure combines existing job counts with these measurements. Free memory below 10% or 512 MiB, or event-loop p95 above 50 ms, defers heavy jobs. Below 5% or 256 MiB, or p95 above 200 ms, it also defers new image/visual-canon jobs. These conservative admission limits are application policy, not a hardware benchmark. They do not cancel already-running GPU work or guarantee a job fits VRAM. Core commands remain available. The host status includes actual RSS/free memory/delay; players and the public display do not receive machine measurements.

`diagnostics.test.mjs` checks canary exclusion, metadata bounds, export-failure isolation, malformed/oversized bodies, ignored cancellation and actual owned-server export failure. `resource-monitor.test.mjs` injects pressure boundaries and checks actual host measurements, schema-field agreement, invalid resources and audience filtering. No real providers, assets or campaign records are used.

`ai-context.test.mjs` verifies container inheritance, source labels, bounded copied inputs and actual captured public/GM requests after an owned fixture restart. Prompt-location checks also verify wrong-audience refusal before transport and the maintained system prompt plus the appropriate policy. Existing action/narration fixtures retain malformed-output rejection, explicit approval and no authoritative mutation from generated prose.

`party-load.test.mjs` runs seven concurrent player connections plus independent host and display sockets through five rounds. It measures 75 persisted command acknowledgements and delivery of each committed revision to all nine sockets, reporting p95/max, runtime, CPU and transport. An isolated source run on Windows x64, Node 24.13.0, Ryzen 5 7600X3D measured acknowledgement p95/max **20.30/22.65 ms** and all-audience delivery **20.07/22.34 ms**. This is loopback, synthetic data and disabled optional services. It proves neither Wi-Fi nor handheld/browser/render latency. Full-suite concurrent runs report their own timings; they are not substituted for physical rehearsal.
