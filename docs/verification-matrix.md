# Overhaul verification matrix

This matrix records what each check establishes, how to repeat it, and where evidence is missing. It does not turn a simulated phone or static markup assertion into a physical-device rehearsal. Current automated baseline: **151 Node tests**, including three stdlib Python cases inside the TTS test, pass with existing installed tools against source and emitted services. All eight workspaces pass lint/build after the completed dashboard code split. Real browser/device gates remain open because local browser use is disabled in Work settings.

## Repeatable commands and isolation

From the repository root, run `npm run lint`, `npm run build`, then `npm test`. For emitted-service execution, run `$env:BDE_TEST_BUILT='1'; npm test` in PowerShell; remove that variable afterward. The full build prepares optional Node service emission needed by launcher tests. Existing `python` 3.10+ on PATH is required for the stdlib-only TTS test; do not install missing dependencies incidentally. Vite currently reports two optional chunks above 500 KB; builds succeed, but physical performance remains unmeasured.

Tests use synthetic SQLite/data under owned ignored `tmp` directories, loopback/ephemeral ports, allowlisted subprocess environments and fake/blocked optional calls. Helpers close their own databases, sockets and processes and remove only their own fixtures. Never replace fixture paths with `_data`, a real campaign, private asset/model stores or a private environment file. No generation, model downloads or live provider calls are part of this matrix.

## Rendered and physical release gates

These are pending procedures, not completed tests. When browser access is available, start only the owned disposable demo helper documented in [tests](../tests/README.md); stop that helper afterward. Never browse a live campaign instance for routine verification.

1. Open separate host, public display and phone surfaces. Test extended display and mirroring; inspect public traffic as well as visible panels. Confirm host credentials/private notes never appear on the TV or in join URLs.
2. At phone widths and TV scaling, complete join/name/ready, private choose/update, acknowledgement/wait, reveal and result. Check touch targets, labels, focus order/restoration, keyboard controls, reduced motion, text alternatives and error states.
3. Disconnect/sleep/refresh one phone while others act; retry after an intentionally lost reply, verify the same seat/accepted choice, and confirm one outcome per action. Revoke a seat and confirm its socket/retry stops.
4. Rehearse on the actual host, TV and seven phones: LAN URL/QR and firewall, 20–30-minute complete game, one restart, pass/deadline/pause recovery, ending and new game. Record device/scaling, duration, observed latency/failures and a go/no-go decision. Stop at any privacy/recovery failure.
5. Keep AI/media/TTS disabled for the baseline. Measure optional capabilities separately only when explicitly configured/authorized; failures must not prevent a legal command or completion. Do not call the demo ready solely because headless checks pass.
