# Bounded narration and stale-result safety

Provider inputs now use the shared [audience/source builder](diagnostics.md): shared narration excludes GM-only/player-only context before transport and refuses a mismatched context. GM-only director/action proposal paths preserve source visibility. AI JSON bodies/text are bounded and provider errors remain generic. Generated prose cannot apply state; prepared drafts still require host review.

Automatic roll prose and host local-model drafts share `createNarration` in `services/game-server/src/narration.ts`. The owner imports no configuration, providers, storage or timers with side effects. Bootstrap injects generation, current scope and server liveness. Production uses a ten-second total deadline, covering provider response/body decoding as well as the initial request. The AI adapter combines caller cancellation with its own request deadline for either existing provider; provider selection is unchanged.

The owner has one replaceable roll slot and one replaceable draft slot. New requests in a slot cancel prior requests. Each invocation captures session ID, mode, round, stage and revision. Committed broadcasts and narration toggles cancel obsolete work; completion checks the entire scope again even without a broadcast. Room replacement changes the session scope. Shutdown disposes both slots before store closure. Draft connection closure also cancels its request. Cancellation/timeout settles the caller even if an injected adapter ignores abort, releases its slot and removes owned timers/listeners. External providers may continue work they already accepted; this does not establish GPU admission or durable external cancellation (CAP-05/06).

A legal roll commits immediately with prepared template narration. Generation begins only through the existing post-commit deferral; failure or timeout retains that fallback and does not replay fallback speech. Successful current prose may replace pending narration; stale prose changes nothing and records no output log. Receipt replay never resubmits narration. Host drafts retain their prepared response on provider failure, blank/oversized text or deadline. A superseded, cancelled or changed-session draft returns a generic 409 so the host can request another draft; it cannot be mistaken for a current successful draft. Rejected provider bodies/errors and generated prose are excluded from the new completion logs.

This owner changes presentation only. It cannot roll dice, mutate HP, apply proposals, change canon or advance a mode. A change to any authoritative table revision invalidates earlier prose conservatively, including an explicit save. Generated pending prose remains ephemeral until another command checkpoints controls; the already committed fallback is the restart-safe value. Existing prepared Party rounds continue without any narration calls in Party profile.

`tests/narration.test.mjs` selects source/emitted owners. Five cases cover valid/failure/blank/oversized completions, deadline with ignored abort and late body, every scope dimension, latest request replacement, caller cancellation and disposal. Actual isolated server checks delay synthetic completions through command changes and room reset, verify 409 drafts and unchanged fallback/action after late replies, then accept current draft/roll prose without another authoritative revision. Exact roll replay makes no additional generation request. The helper's bounded delay and replies run in-process with an allowlisted child environment; no provider, model, private library or real campaign is accessed. These checks do not prove speech playback, generated-content quality, browser interaction, structured output/redaction across other routes, or complete media-router lifecycle consolidation. Speech and automatic scene submission are now separate [optional work owners](optional-work.md); pending prose is spoken only through the host browser request/playback flow.
