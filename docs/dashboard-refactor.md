## Extraction history

The extraction preserves the seven panels' original JSX and existing advanced-mode conditions. They consume the same host-only data and do not fetch independently. App is reduced from about 3,600 lines to about 2,700; this is evidence of moved ownership, not the completion criterion. No new framework, dependency, workspace or global fetch patch is added.

The connection now shares socket/timer ownership with Party/companion rather than maintaining another bespoke reconnect loop. It uses current render callbacks, stops on expired credentials, detects silent connections, ignores old socket callbacks through the shared owner and exposes generic connection errors beside status. Existing bootstrap REST reads remain in App. Reconnect receives the server's authenticated connected snapshot; there is no added polling timer. Roll ID dedup is bounded to 128 entries and roll-log display to the existing 12. Numeric results remain server-authoritative; repeated live roll delivery does not reopen the overlay.

Envelope checks reject missing payloads and invalid rolls. They are deliberately not full nested host snapshot/runtime validation; ROOT-03/04 must still consolidate the remaining protocol definitions. The existing command-response/bootstrap casts and state ordering are not made a complete client consistency model by this extraction. Other existing UI gaps, including placeholder cleanup/export/error-loading handlers and optional inference/audio lifecycle, remain outstanding rather than being declared working.

`tests/host-client.test.mjs` exercises malformed envelopes, valid saved numeric roll rendering and repeated-roll suppression. An isolated real server supplies authenticated connected frames, host context, runtime and saved roll/session updates, including reconnect. All seven extracted panels render to static HTML from producer data or empty states. The existing shared-connection tests cover remount, socket/timer cleanup, old callback suppression, silent heartbeat and revocation. These checks do not mount React effects in a real browser or prove layout/focus/WebGL/audio behavior.

The next extraction moves character, table and scene/AI state into persistent hooks and seven additional panels, reducing App to approximately 1,460 lines. ## Current acceptance status

The remaining bootstrap, reports, host controls and narration have moved out of App. The prior placeholder cleanup/error/export handlers are replaced by real authenticated requests. Save feedback is independent of export feedback; failed scene commands retain the typed title and cannot trigger ambience/search. These side effects follow a confirmed scene response. The existing search checkbox remains available; no new integration or automatic provider fallback was added. Host actions use ten-second abort deadlines, cancel owned requests on unmount and reject results from a disposed request generation. A slow bootstrap read cannot overwrite a newer socket/command update. Memory and host buttons have synchronous per-action duplicate-click guards, without claiming a global command arbiter or restart-safe host queue.

Narration owns its poll/initial timers, synchronous busy guard and playback resources. It suppresses responses from an earlier scene/view epoch, prevents overlapping narration polls, stops prior playback on scene changes and releases context/source/element/object-URL resources on disposal or rejected playback. Unlock failure stays visible as locked; readable text remains when optional speech fails. These improvements do not complete CAP-02/05/09: responses still lack full session/round/revision binding, cancelling a client request does not prove backend inference cancellation, and independently mutable/interruptible host controls and physical autoplay/audio remain open. Existing local-audio endpoint/stale-poll gaps also remain.

## Controller response adoption and generated scene regression

Table/media actions, scene packet/queue/local/director reads, audio library/playback/cue reads and character creation now pass untrusted JSON through shared response guards before state updates or draft clearing. Malformed table confirmations preserve the existing retry ID and condition draft. ## AI proposal application and narration confirmation

AI suggestions now use the shared structured proposal contract and accepted skill/difficulty maps. The injectable `ai-actions.ts` client validates proposal, action and narration confirmations. Applying a suggestion sends the server-required `type` field (the former client sent `action`, causing rejection), checks returned fields and shows applied/failure status while retaining a failed proposal. The narration checkbox starts unconfirmed, changes its displayed value only after matching server confirmation, preserves the last confirmed value on failure and exposes saving/failure feedback. A late bootstrap response cannot replace a later toggle. These changes do not implement complete async session/revision cancellation or a durable host retry queue.

`ai-actions.test.mjs` covers mocked producer acceptance/rejection, explicit action application, restart, schema/parser compatibility, malformed confirmations and static feedback. The current baseline is 74 tests; dashboard initial/lazy bundles are 261.32/692.49 KB. Browser mounting, focus/interaction and audible narration remain unverified.
