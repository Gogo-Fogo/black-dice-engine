# Server responsibility extraction

ENGINE-01 remains in progress. The executable entrypoint still owns memory/context assembly, optional capability orchestration and transport composition. Extractions follow tested responsibilities rather than a target line count; they do not declare the whole engine reusable.

## Table reads and session summaries

`table-read-routes.ts` now registers the five table read/export routes through one installer with snapshot/runtime readers, an explicit summary directory and injected clock. It owns response formatting and host export file creation, not domain state, configuration discovery or SQLite. `session-summary.ts` contains the pure host Markdown formatter and existing filename sanitizer. It has no import-time I/O, state singleton or environment lookup; memory export callers reuse the same sanitizer.

| Route | Preserved behavior |
| --- | --- |
| GET `/api/party` | Compact name/class/HP/claim-label list, with `unclaimed` fallback |
| GET `/api/rolls` | Up to 20 recent records, each containing `name`, `dice`, `modifier`, `total`, `note`, `time` |
| GET `/api/runtime-status` | Current runtime result, projected for non-host audiences by existing middleware |
| GET `/api/session-snapshot` | Current host snapshot or existing player/display projection |
| GET `/api/session-summary.md` | Host private Markdown attachment/export; non-host projected Markdown without host export path or file creation |

The old index registered GET `/api/rolls` twice. Express always used the first compact handler, making the later full-record handler unreachable. The installer preserves that compact response and removes the unreachable registration. Full roll records remain available in already-projected snapshots/live frames; no second endpoint or query mode was invented. Both apps submit rolls with POST and consume full records from snapshots/frames, so no app endpoint migration is needed. POST rolls, receipts and authorization remain in their existing command boundary.

The installer stays after `installSessionAccess`, profile admission and command middleware, at the previous first table-read registration. Exact-path GET runtime/snapshot/summary handlers move before unrelated images/speak/player handlers; no matching middleware or wildcard handler changes their authorization. Session middleware still intercepts non-host summary requests before the host export handler, so they neither format private host data nor write files. The export handler additionally checks its authenticated identity before formatting/writing. Do not mount these private readers before session access/projection middleware.

The host filename and Markdown footer now use the same injected timestamp, avoiding a date mismatch if export crosses midnight. Existing host sections, locale-based display dates, private notes and headers remain. Export errors continue through the generic error handler; no filesystem path/error detail is sent in an error body. File names use the existing sanitized campaign-title component inside the configured export directory. No real export directory or source material was inspected.

Pure checks cover populated/empty sections, deterministic formatting, safe filename parts and unchanged inputs.

Existing TTRPG integration continues join/claim, roll, propose/approve, sheet state, reconnect, filtered summary, lost-reply replay and restart. These checks establish headless compatibility, not rendered controls or physical-device acceptance. Remaining ENGINE-01 work includes scene/memory assembly, capability routes and socket delivery with preserved transaction/projection order. ENGINE-02–05 still require both modes to consume proven shared boundaries; these extractions alone do not establish that interface.

Rollback must restore the index registrations and formatter together, including callers of the shared sanitizer, while keeping only one compact GET roll handler. No schema, stored record, resource path, dependency or startup profile changes are part of this slice.

## State event application and approval routes

`state-events.ts` now owns HP changes, condition add/remove, resource assignment, initiative set/clear and the existing proposal summary strings. Its factory takes current-character lookup, event recording and snapshot publication hooks. It mutates the caller's current character within the existing command boundary; it is not yet a pure reducer or a reusable mode interface. Lookup happens per operation, so a rollback that replaces collection objects cannot leave the owner targeting an abandoned character reference. HTTP, SQLite, approval queue ownership and file exports stay outside this module.

The shared `isStateEventRequest` guard now runs before application. This closes a queued/persisted-data path that bypassed direct-command checks: a malformed initiative value formerly fell back to null and cleared initiative. Malformed queued values, unknown kinds and non-finite numbers now fail with a generic 400 before mutation/logging/publication. Valid values preserve clamping, no duplicate condition log, unchanged response shapes and existing event visibility/actor labels. HTTP integer/range/ownership validation remains in session/command middleware. The structural guard does not replace complete persisted-record validation or authorize a queued proposal.

`state-event-routes.ts` registers queue reads, propose, approve, reject and direct state application at the same index position after command/session middleware. It receives the shared queue, state owner, existing role guard and record/publish/memory hooks; proposal timestamps use the injected server clock. The scene-packet queue still shares the same queue and summarizer. Approval keeps apply/approval-log/memory/publication ordering. Existing command hooks still capture/restore all collections and defer broadcast/export effects until durable commit; the new modules do not open a second transaction or write files independently.

`tests/state-events.test.mjs` covers all five state kinds, clamps, condition no-op logging/publication semantics, missing targets/resources and fresh lookup after object replacement. Malformed values leave the character/log/publication untouched. An actual isolated server verifies player ownership and forged-submitter normalization, forbidden direct/approval/queue access, receipt-write failure with exact state/queue/revision/memory rollback and no export, successful retry/replay, rejection, restart and no repeated memory file. A separate owned fixture corrupts only its synthetic persisted proposal, then confirms approval cannot clear saved initiative or discard the proposal. The invalid proposal remains available for deliberate rejection; broader loaded-data/UI validation remains ROOT-03 work.

Rollback of this slice must restore both route and domain callers together; preserve the shared guard if reverting only the extraction. No schema or persisted format changes occur. These tests do not establish browser interaction, general scene-packet validation or a completed ENGINE-01/02–05 abstraction.

## Character creation, claims and release

`character-routes.ts` owns the existing creation and claim/release HTTP handlers. Two installers preserve the original creation and claim registration positions among unrelated media/state routes. Both share explicit party-array, record, publish, persistence and role-guard hooks. They perform no import-time initialization, open no database and own no presence/session state. Character creation now uses the existing shared publication helper for the same snapshot/runtime broadcast sequence.

Session middleware still issues identity, normalizes player client IDs/labels and rejects forged actors. Command middleware still validates, replays accepted receipts before mutable ownership checks, checks revisions and owns capture/restore/durable commit/deferred publication. The shared party array is restored in place on rollback, preserving the installers' reference. Creation remains a bare character response with command metadata; defaults and validation remain unchanged. A successful switch clears the player's previous claim and assigns one target together. Release clears all of that player's claims. A repeated accepted claim returns its stored result without reclaiming a sheet whose ownership has since changed.

Two actual source/emitted server tests in `tests/character-routes.test.mjs` cover creation validation/defaults, denied creation, receipt-failure rollback, single creation and exact replay after restart. Claim checks cover forged identity/label normalization, conflicting claims, display denial, own/other/display note filtering, atomic switch/release rollback, competing commands with one expected revision (one success, one conflict), restart and old-claim replay after another player acquires the released sheet. The replay changes neither ownership nor revision/history. Only original synthetic characters/notes and owned disposable databases are used.

Character visual-canon work remains with media orchestration. This extraction does not introduce a new membership model, move authority into the browser, validate all legacy character records or complete mode abstraction. Roll/control, context/memory, capabilities and socket responsibilities remain. Rollback must restore both installer sites and their handler bodies together; no schema, persisted format, profile or client endpoint changes are required.

## Action controls and rolls

`ttrpg-action-routes.ts` registers action setting, narration toggle, scene setting, explicit save and roll submission together at their former position after character claims. It receives caller-owned collections, current control accessors, snapshot/event/persistence hooks, deferred-effect delivery and the existing optional-service configuration/transport. Accessors target the entrypoint's current scalar values, including values restored by a failed command; no captured copy or second transaction owner is introduced. Middleware still validates identities, payloads, revisions and durable replay before handlers run.

Dice parsing/crypto sampling remain in `dice.ts`. Roll records, event/broadcast order, action completion, fallback prose and response shapes remain compatible. Optional narration and scene-image work delegates to injected owners; the installer no longer performs ComfyUI requests or server self-requests for speech. Narration uses the shared [narration owner](narration.md); speech and scene submission use [bounded optional work](optional-work.md). The host browser owns speech requests/playback. Scene and roll submissions run after durable command success. Manual media-router lifecycle now uses the bounded owner too; approved asset serving remains open.

`tests/ttrpg-action-routes.test.mjs` creates and claims two original synthetic sheets, completes a group action, and injects a receipt-write failure on the final roll. Roll/history/revision, current action and pending narration all remain unchanged after failure. Retry clears the action and prepares fallback narration once; exact replay and restart preserve the receipt, pending narration and disabled narration setting. Existing host-control and TTRPG suites cover scene/save/export, ownership, projection and roll delivery. Source/emitted verification uses only disposable fixtures. Rendered controls and real optional providers remain unverified. To revert the extraction, restore this complete registration block and remove its installer call together, preserving upstream middleware and deferral.
