# Shared dice and sound presentation

Both TTRPG views consume `apps/dice-presentation.mts` and `apps/dice-audio.mts`. The four former per-app `dice3d.ts`/`diceSound.ts` copies and their startup preload calls are retired. Party remains independent of dice presentation. The phone imports the shared renderer through its optional lazy presentation chunk; the dashboard keeps its existing TTRPG bundle. No dependency, package, schema, authority or service-runtime change is needed.

The renderer API is `renderDiceOverlay(container, notation, onDone)`, returning `throwDice()` and idempotent `dispose()`. `onDone` reports cosmetic completion or model failure; it never generates or returns a gameplay result. Both wrappers display the server's saved `RollRecord.total`; the dashboard now displays that value immediately, including during unavailable/loading animation. There is no face-to-total alignment guarantee. At most twelve visual dice are rendered for a larger notation; the server's full notation and result remain authoritative.

Each overlay loads its own GLTF tree, avoiding a global cache with ambiguous resource ownership. Its within-overlay clones share that tree's resources. Cleanup traverses the owned tree and disposes each geometry, material, texture, closable bitmap image and skeleton once, then clears the scene and disposes the renderer. It removes only its own canvas, animation frame and resize listener. Late load completion after disposal immediately releases the model instead of attaching it or calling completion. Setup failure and reentrant completion disposal also clean up. Resize and animation callbacks cannot revive a disposed instance. Settled dice stop scheduling animation frames; a later resize redraws the saved presentation once. Browser HTTP caching may still serve repeated asset requests; this is not a cross-overlay JavaScript model cache.

`playDiceRollSound()` returns an idempotent stop function. Each sound owns its own element and bounded timer. Completion, rejected playback and overlay unmount pause that element, clear its timer and release its source. A prior sound timeout never acts on a newer sound through a module-global variable. Neither module starts playback at import. Phone tap or explicitly enabled shake opts into sound; rejected playback leaves the saved result readable. Existing dashboard ambience/narration unlock and playback controls are unchanged.

Both wrappers gate throw/sound with an instance ref. Companion receipt/live paths already share a bounded roll-ID deduplicator using current ownership; historical reconnect snapshots restore state without playing old rolls. The dashboard now ignores duplicate live roll IDs for presentation, deduplicates its roll list and keys overlays by saved roll ID. Replacing an overlay releases its audio and renderer; rerendering does not start sound. Role-specific wrappers retain their controls: phone motion opt-in and explicit close, dashboard click and timed dismissal.

`tests/dice-presentation.test.mjs` uses real Three.js in-memory scene/resources with an injected fake renderer, loader, clock and audio. It checks resource ownership, duplicate cleanup, frame/listener/canvas cleanup, resize, late completion/failure, setup failure, reentrant disposal, independent audio timers and rejected playback. It does **not** create a browser or WebGL context. Existing Party integration tests issue HEAD requests for all six bundled dice model paths plus the sound under `/host/` and `/player/`, asserting nonempty non-HTML assets without reading their bodies. Both apps still build with existing installed dependencies and `base: "./"`.

Local browser use remains disabled in Work settings. Real GPU output, mobile audio unlock/motion, screen layout and physical device performance remain unverified and are covered by the still-open UX/rehearsal gates. Two existing >500 KB optional TTRPG/dice bundle warnings remain. This extraction establishes implementation ownership and regression coverage, not a rendered-device readiness claim.
