# Runtime configuration and build verification

The Node runtime configuration source is now [packages/runtime-config](../packages/runtime-config/README.md). Its private manifest has four real service consumers and no external dependencies. It emits native ESM and declarations with NodeNext. Browser contracts remain in a separate ES2022 package without Node types; neither app imports runtime configuration. Both apps retain Vite `base: "./"`, their existing API/image/health/WebSocket development proxies, and no-emit TypeScript with explicit source-extension imports for shared `.mts` helpers. The game server compatibility config module re-exports the maintained package, preserving existing callers.

Root `build` visits **eight** workspaces: contracts, runtime configuration, two apps and four Node services. Root pretest/prelint build both shared packages; relevant development prerequisites build only their required shared packages. The Party build visits five workspaces: both packages, both apps and the game server. It verifies the new emitted package before startup. Existing Node/TypeScript/Vite installations suffice; no install/link/download was run. Consumers intentionally use repository-relative emitted entrypoints because newly added workspace links do not exist in the current installed tree. Lockfile changes add only local metadata; external versions/resolutions are unchanged.

All Node services now consume process environment without dotenv auto-discovery. Audio and Comfy previously looked above the repository; runtime previously used cwd. Those lookups are removed. Explicit examples for `node --env-file=<chosen-file> ...` are in [.env.example](../.env.example); the private `.env` was not opened. The example removes duplicate active keys and machine-specific active data paths, documents actual service ports/store names and gives Python TTS explicit model/voice settings.

Configuration accepts decimal ports 0–65535, with loopback default for all Node services. All relative database/export/backup/optional-store paths resolve from the repository root independent of cwd. The database default is still `_data/black-dice-engine.db`; data is not moved or opened for these checks. Optional stores remain empty when absent, and audio explicitly refuses to scan an empty root. Base URLs require HTTP(S) without credentials/query/fragment and errors name the variable without echoing its value. Party ignores optional endpoint/store values before URL parsing and clears AI endpoint/key use. Full-profile provider/model defaults are retained, with supported provider names validated.

The two legacy direct Comfy submissions now use explicit `BDE_COMFY_API_BASE`, have a bounded request timeout and stay disabled when absent. Configuring a router alone no longer activates a hidden hard-coded localhost:8188 submission. Optional workflow behavior, provider-side persistence/cancellation and the direct workflow bodies remain broader capability work. This change does not enable providers, LAN, cloud or telemetry.

## Remote AI consent

Full profile defaults to host-local inference. `BDE_ALLOW_REMOTE_AI=0` blocks the selected provider before any completion request when its actual base URL is outside literal IPv4/IPv6 loopback or `localhost`. This includes LAN model servers and Ollama-compatible hosted endpoints. `BDE_LLM_PROVIDER`, an API key or an endpoint URL alone is insufficient consent. A host may explicitly set `BDE_ALLOW_REMOTE_AI=1` in their chosen environment to permit the selected off-host provider; no setting was enabled by this change. Only `0` and `1` are valid. Party ignores the flag and always disables inference.

OpenAI-compatible services bound to loopback remain usable without remote consent. Selecting OpenAI/chatgpt with its default cloud URL requires consent and the existing API key. Failure or policy refusal never switches providers; prepared fallback remains available. Both provider transports reject HTTP redirects, so a local endpoint cannot silently redirect a context-bearing request elsewhere. A deliberately configured local proxy can itself forward data; the host must trust software running on their machine. This policy controls application requests, not arbitrary proxy internals or DNS/network configuration.

`remote-ai.test.mjs` checks endpoint normalization/locality, aliases, explicit consent, Party override and invalid flag values, then invokes source/emitted adapters in nine isolated allowlisted environments. Fake fetch proves blocked cases make zero requests, selected allowed cases send only to the selected URL with redirects refused, and local failure does not fall back to remote despite a configured synthetic key. No remote provider is contacted. Capability reachability/readiness and full prompt/output audits remain CAP-01/03.

`BDE_BACKUPS_DIR` configures the game-server online snapshot owner as well as the runtime facade. `BDE_AUTO_BACKUP` accepts only `1` (default) or `0`, controlling process-start and graceful-end snapshots. Manual operations require host authentication; runtime requests delegate credentials to the game server. Launchers isolate backups beside explicitly selected session data. The previous unauthenticated startup main-file copy is removed. See [backup behavior and restore limits](backups.md).
