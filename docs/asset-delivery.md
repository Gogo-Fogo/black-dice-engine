# Approved asset delivery

`GET /api/assets/:assetId/content` accepts a record ID and a normal Bearer session credential. The record must be approved. GM sees approved records; players also require `player_visible` or `public_demo`; the public display requires `public_demo`. Missing/private/unapproved records return the same generic 404. Credentials are rechecked after asynchronous file work. No credential is placed in a query string or image URL.

The file must have an absolute recorded path inside a configured `BDE_MEDIA_OUTPUT_ROOT` or `BDE_COMFY_OUTPUT_DIR`, and its resolved target must remain inside the resolved root. Directory/junction escapes fail. Only bounded regular files up to 64 MiB are read, with a fixed-size read allocation and post-read size check. Extensions, asset kind and signatures must agree: PNG/JPEG/WebP images, WAV/MP3 audio or MP4 video. SVG/HTML, unknown kinds/types and missing/mismatched files fail. These are transport-envelope checks, not codec decoding or an anti-malware scanner. Files must remain host-owned; concurrent replacement of mutable local files is not an approval workflow.

Responses set an explicit type, `nosniff`, sandbox CSP and `no-store`. The old `/images/*` file server returns 404, and `/api/images` lists only approved record IDs/content URLs rather than scanning a directory. Player asset metadata excludes local paths, prompts and workflow metadata. Existing legacy character image filenames require migration to records; no arbitrary-filename fallback remains.

`POST /api/assets/:assetId/approve` requires host authority and an existing generated/approved record. It validates the recorded file and persists approval before publishing; failed storage restores the former status. It cannot accept a request-supplied filesystem path or change the record's audience. The dashboard offers approval for the listed audience. Generated metadata alone never grants player access. File discovery/import, authoring actual record paths and stronger content review remain separate workflows.

Gallery image components fetch the credentialed API and own/revoke blob URLs on source changes/unmount. Late reads cannot publish a closed image. Static React and transport tests cover URL ownership, denied/approved content, signatures, junction/path escape, size bounds, failed approval persistence and restart. Fixtures create only synthetic envelope bytes in owned temporary folders; no external outputs, private files or real images are accessed. Browser rendering and actual media decoding remain unverified.
